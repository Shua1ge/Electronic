# 统一图纸候选与图表联动复核（Ubuntu / Qwen3.5 2B）

这个入口同时处理光缆路由图、设备连接图和柜内配线图。保留原有 macOS Audit 和 Fast v0.3 命令；本功能在独立分支演进。继续使用缓存的 `Qwen/Qwen3.5-2B` NF4，不需要新增模型，不会上传工程图。

## 一次处理三份图

使用现有 Ubuntu 虚拟环境，不要通过面向 macOS 的 `pyproject.toml` 重装环境。下面的路径是本次测试的本机文件位置，其他机器需替换为自己的输入路径。

```bash
cd ~/Electronic-fast-v03
source ~/venvs/electronic-qwen/bin/activate
python scripts/drawing_pipeline.py \
  ~/文档/03.pdf ~/图片/10.pdf ~/图片/11-04-1.PDF \
  --output ~/drawing-review-$(date +%Y%m%d-%H%M%S) --serve
```

模型在整个批次只加载一次。程序完成抽取后显示 `http://127.0.0.1:8765`，用本机浏览器打开；切换左上角的图纸即可检查三个结果。服务器只监听本机，关闭终端或 Ctrl+C 后需重新启动。端口被占用可使用 `--port 8766`。再次抽取必须使用全新目录，避免覆盖人工修改。

已完成的批次可直接打开，不会重新调用模型：

```bash
python scripts/review_server.py ~/你的运行输出目录 --port 8765
```

## 实际处理流程

每页先检测空间对象、设备层级和线段。光缆图使用圆形及矩形站点；设备图提取柜体、单元，以及由线路端点提出的端口候选。连接使用对象 ID 和页坐标，不通过名称猜测同一设备，不需要先人工确认名称。

几何模块从矢量端点追踪折线；交叉点不自动创建连接，柜体边框不充当线路。粗线的近重合轮廓做描边归并，真实平行线路保留。方向一致、相向且唯一的短断口允许产生续接候选，记录中明确显示需要复核；多个分支不自动替用户选择。未绑定路径也保存，避免只检查已生成的记录而看不到遗漏。

Qwen 分别读取单个对象/端口名称及每条连接的局部标注。模型输入只使用一张目标标记局部图，复核证据同时保存未标记原图和原图/标记图对照。长折线目前选取最长线段附近读取标注，其他位置的标注可能漏读。站名不由传统 OCR 否决，重复的同一读法不会形成假歧义；明确的模糊标志和不同读法会保留。

柜内连线的线号、纤芯范围和去向文字保留到“其他标注”字段，不会被强行解释为光缆芯数或长度。模型提出的文字框属于候选定位。芯数、长度按完整数字和单位解析，标注与路径竞争关系单独记录。可用值先填入候选表；空间归属不明不会被显示为人工确认。当前尚不自动解释所有图例、线束或设备内部逻辑连接，也不保证枚举所有未连线的备用端口。

## 在复核页修改

点击连接记录，原图自动定位对应路径和端点。选择“图上选”可修改端点，再点击“保存修改”；未绑定时的红色虚线只是两个端点的示意，不代表原图存在该线路。端点变化会清除旧路径，保留参数值并要求重新核对归属。

对象与端口页可以修改名称、类型和父设备。名称在所有关联记录中同步显示；修改已确认记录的关联对象后，该记录回到已修改状态。通过父对象区分不同设备中重复出现的端口编号。

“补充连接”按顺序点选两个对象；“补充端点”允许在原图点击新位置并命名。“待补路径”显示没有被有效连接使用的图形路径，可以选择其中一段再指定两端。待补路径也包含部分边框和非线路图形，不等同于漏检线路数量。

勾选记录后可批量确认或排除。只有这些明确的人工操作会产生确认状态。顶部“导出 Excel”读取当前已保存数据生成工作簿，包含连接、对象/端口、路径覆盖和修改记录。抽取时生成的 Excel 是初始快照，修改后应通过复核页重新导出；直接在 Excel 修改不会自动回写。

## 数据与回放

每份 PDF 的子目录中，`graph.json` 是当前统一数据；`initial_graph.json` 是初始候选快照；`calls/` 保存模型原始回答、实际输入图、提示词、错误及耗时；`tasks/` 保存局部证据；`pages/` 保存整页图。人工事件保存在 `graph.json` 的 `events` 中。服务使用修订号拒绝旧窗口覆盖新修改。

批次目录中的 `batch.json` 索引所有图纸。输入文件 SHA256、模型 revision、抽取代码哈希和处理时间保存在每份图的 JSON 中。所有输出均留在本机，真实 PDF 和运行产物不应提交到仓库。

```bash
# 无 GPU 的几何及界面准备
python scripts/drawing_pipeline.py a.pdf b.pdf --output new-geometry --mode geometry

# 回放保存的回答，不加载模型
python scripts/drawing_pipeline.py a.pdf --output new-replay \
  --mode replay --responses-dir saved-run/01-a/calls

# 控制实验规模，0表示全部；未执行的任务会记录call_budget
python scripts/drawing_pipeline.py a.pdf --output new-small --max-calls 12

# 本功能测试（包含临时本机 HTTP 服务器）
python -m unittest discover -s tests -p 'test_drawing_review.py' -v
```

`--kind route` 或 `--kind cabinet` 可覆盖自动类型判断；混合批次默认自动判断。默认关闭下载，缓存缺失时先检查模型路径，只有明确需要联网才加 `--online`。

## 验收边界

模型与几何结果仍是候选，不报告未经独立人工标注的准确率。三份开发图的运行成功只能验证流程、输出和复核操作，不能证明泛化效果。比较手工录入与本流程时，需要统计模型等待、查错、补漏、修改和导出的总时间，以及最终错连、漏连、端口归属和参数错误。当前版本尚不直接生成五类正式业务申请表，也没有跨图自动合并设备身份。
